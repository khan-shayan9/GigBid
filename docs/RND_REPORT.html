GigBid: R&D Report (engineering design review)

AI-4016 Assignment II. Every number cites a file in evals/results/ or a commit. Status at submission: Phases 0–5 built (data, our GigSim, MCP servers, RAG, graphs and memory); the web app, deployment and signature extension are not built.

1. Problem and constraints

Freelancers spend hours scanning feeds, waste Connects on poor-fit jobs, send generic proposals and meet scams. GigBid scouts, assesses, drafts and handles replies; the freelancer decides. Never automated: sending a proposal or message, and spending Connects. Every write goes through a LangGraph interrupt() approval and an idempotency key. Budgets (agent/config.yaml budgets): 30 graph steps, 12,000 tokens per job, at most 2 Critic revisions, 2 node retries with backoff. Over budget a thread ends in needs_attention; a dependency that stays down ends it in dead_letter.

2. Architecture

Bid graph (agent/graphs/bid_graph.py): Job Analyst, Risk Assessor and Fit Matcher run in parallel, then a decision node (the only bid/skip authority), Pricing, Writer, Verifier, Critic (at most 2 loops), Compliance Guard (the only node that can block), approval interrupt, submit. Conversation graph: intent classification (scam signals end the thread), Workspace slots, reply draft, compliance, approval, send. Hand-offs are Pydantic objects (agent/handoffs.py). Marketplace port with GigSim and live Upwork adapters behind the Marketplace MCP server. MCP surface: our Portfolio, Marketplace and Workspace servers plus GitHub and Upwork, with per-node tool allowlists (docs/TOOLS.md). Stores: Postgres checkpointer (agent/checkpointing.py), pgvector evidence index, LangGraph store for style and outcome memory written only by agent/memory/promotion_rules.py. The crash/resume test (tests/integration/test_crash_resume.py) kills the run after the marketplace accepted a submission; the resumed and replayed runs still submit exactly once, on MemorySaver locally and Postgres in CI.

3. R&D A: tool granularity

Hypothesis: coarse tools save tokens but hurt accuracy; per-node fine tools with rewritten descriptions are most accurate and nearly as cheap. Setup: 40 tasks with known calls, gpt-oss-20b, first call scored. Results (rnd_a_tool_granularity_openai_gpt-oss-20b.json):

Conclusion: coarse dispatchers cost accuracy (4 invented tool names). Allowlisting cut tokens by two thirds but dropped arguments (dry_run, filters); rewritten descriptions fixed that. We ship fine tools behind allowlists. Limits: one model, one run, our own tasks; "best" was written after seeing failures, so it is optimistic.

4. R&D B: RAG variants

Hypotheses (written before running): H1 decomposition + hybrid raises Recall@5 by 10 points on jobs with ≥4 skills; H2 reranking raises MRR by 0.05. Results (60 gold dev jobs, rag_retrieval_dev.json): V0 0.219 / 0.285 (Recall@5 / MRR); V1 decomposition 0.297 / 0.412; V2 hybrid 0.258 / 0.316; V3 rerank 0.242 / 0.324; V8 corrective 0.117 / 0.183; V1+V2 0.294 / 0.355; V1+V2+V3 0.242 / 0.379. H1 not supported (+7.2 points). H2 not supported (+0.025 MRR; Recall@5 fell). Ablation (rag_ablation_dev.json): removing the reranker gives the best Recall@5 (0.294). By persona, V1 gains on data_analyst (0.283 to 0.475) and ai_ml_engineer, and slightly loses on fullstack_dev. Claim verification (proposal_eval_dev.json, 9 jobs per variant): unsupported claims per proposal 0.33 to 0.00 (V0) and 0.44 to 0.22 (V1). Better retrieval did not raise the GigSim reply rate (0.556 for both): simulated clients decide mostly on opening, named skills and budget. Ships: V1. Limits: small samples, held-out split not run, judge uncalibrated, gold labels favour lexical retrieval.

5. R&D C: single agent vs supervisor vs our graph

n = 7 dev jobs (Groq daily quota), both baselines on gpt-oss-120b (rnd_c_dev.json, docs/RND_C.md). Decision accuracy: ReAct 0.857, supervisor 0.857, our graph 0.143 in the first run (it bid on all 7). Cause: the Fit Matcher counted any search hit as coverage, and regex risk missed a fake-cheque scam and an injection aimed at AI writers. Fix (commit bb621ff): an evidence-score threshold of 0.65 chosen on 80 other dev jobs (fit_threshold_dev.json), plus two risk signals in config. Rerun: graph 0.571, scam and injection skipped, the bid job still bid. The supervisor never bid on the one bid job and flagged 2 non-scams as scams. No architecture called a write tool; only our graph guarantees that structurally. ReAct wins on budget/domain skips that fit and risk rules cannot see. Limits: n = 7, and the fix was tuned after seeing these jobs.

9. Safety and platform respect

Never: auto-send, auto-spend Connects, scrape, browser automation. Enforced by graph structure (submit only after an approved interrupt; edits re-checked by Compliance), idempotency keys, per-node tool allowlists, untrusted-text delimiting in prompts, PII masking, and Compliance patterns for contact details and off-platform asks. What still gets through: regex risk misses scams it has no pattern for, and the verifier left 2 unsupported claims in one V1 proposal.
