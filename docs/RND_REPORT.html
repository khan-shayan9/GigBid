GigBid: R&D Report

AI-4016 Assignment II, written as an engineering design review. Every number cites a file in evals/results/, a trace or a commit. All measurements are on the dev split; the held-out split has not been run. Repository: github.com/khan-shayan9/GigBid.

1. Problem and constraints

A freelancer spends hours scanning job feeds, pays Connects to bid on jobs that were never a fit, sends generic proposals and meets scams. GigBid scouts saved searches on a schedule, assesses each job (requirements, client risk, portfolio fit), recommends bid or skip with a price, drafts a proposal whose claims cite portfolio evidence, and drafts replies to clients. The freelancer decides.

Never automated: sending a proposal or a message, and spending Connects. Every write goes through a LangGraph interrupt() that the user answers in the web app, and runs with an idempotency key. Also out of scope: scraping, browser automation, session cookies.

2. Architecture

Next.js web --JSON+SSE--> FastAPI --enqueue/resume--> Arq worker --> LangGraph (bid graph, conversation graph)
                                                                        |  agent/mcp_client.py (per-node allowlists)
                     Portfolio MCP (ours)  Marketplace MCP (ours)  Workspace MCP (ours)  GitHub MCP
                                                  |
                                           MarketplacePort --> GigSim (ours)  |  upwork_live adapter --> Upwork MCP
Stores: Postgres (checkpointer, LangGraph store, pgvector), Redis (queue, run flags, events). Traces: Langfuse Cloud.

Bid graph (agent/graphs/bid_graph.py): Job Analyst, Risk Assessor and Fit Matcher run in parallel; a decision node (the only bid or skip authority); Pricing; Writer; Verifier; Critic (sends the draft back at most twice); Compliance Guard (the only node that can block, with the reason shown in the UI); a dry-run preview; the approval interrupt; submit. Conversation graph: intent classification (a scam signal ends the thread), Workspace slots for interview requests, reply draft, compliance check, approval, send. Hand-offs are Pydantic objects (agent/handoffs.py).

Marketplace port. The Marketplace MCP server reaches the marketplace only through MarketplacePort; marketplace.mode picks GigSim or the live Upwork adapter (OAuth 2.1, tokens encrypted per user). MCP surface: Portfolio (3 read tools), Marketplace (7 read and 3 write tools with dry_run, idempotency keys, Bearer auth, a rate limiter and an audit log), Workspace (slots, holds, email drafts), plus GitHub (portfolio ingestion only) and Upwork (docs/TOOLS.md).

Why each agent exists. Each one owns a decision that a later step relies on: the Analyst turns untrusted text into a JobSpec; the Risk Assessor stops scams before any effort is spent; the Fit Matcher gives the decision a reason and the Writer its citations; the Verifier enforces R5 claim by claim; the Critic and Compliance Guard are separate because only Compliance may block. The Analyst, Fit Matcher, Pricing and Critic are rule-based shortcuts (marked shortcut: in code), and the Risk Assessor is rule-based by design (weighted patterns in config); the Writer, Verifier and the Client Liaison's reply call models.

Persistence and memory. The Postgres checkpointer saves every step; a crash after the marketplace accepted a submission still submits exactly once on resume and replay (tests/integration/test_crash_resume.py). Style and outcome memory are written only by agent/memory/promotion_rules.py (R7); no node reads them yet. Production (Phase 7): graph segments run in the Arq worker, scouting and outcome sync are crons, every thread is one Langfuse trace with node and tool spans and PII masked, and CI runs unit, contract and Playwright tests plus the 30-job smoke eval with gates. Diagrams: docs/ARCHITECTURE.md.

Hypothesis: coarse tools save tokens but cost accuracy; fine tools behind per-node allowlists, with rewritten descriptions, are the most accurate and nearly as cheap. Setup: 40 tasks with known correct calls, gpt-oss-20b, first call scored. Source: rnd_a_tool_granularity_openai_gpt-oss-20b.json.

6. The change request

The real text of the 2 Nov policy update was not provided, so we assumed one (data/policy_pack/v2.yaml, marked assumed: true): proposals must carry an AI-assistance disclosure, and Connects surcharges apply (+4 for budgets of $1,000 or more, +2 for an hourly maximum of $60 or more). What we edited (commit 3303de5): config (policy.version, GIGSIM_POLICY), the writer and verifier prompts, and test fixtures. No node code and nothing under the frozen gigsim/. Measured (policy_v2_diff.json): of 18 Phase 4 drafts, 100% pass v1, 0% pass v2, 100% pass v2 once the disclosure line is added; mean Connects on 522 dev jobs rose from 4.32 to 4.96, and 115 jobs cost more. It took about 15 minutes, which says the policy and the costs really are data.

7. Signature extension: X1 agency mode

What we built. A team of three freelancers (the three personas). With agency mode on, a new bid thread's first run segment runs the shipped Fit Matcher on every member's Portfolio server in parallel, and a router (agent/nodes/router.py) returns a RouteDecision: the highest fit score, then the stronger mean evidence score, then the first member listed. The bid graph then runs unchanged as that member (portfolio, GigSim user, Connects); approve and retry act as the thread's member. The router only picks a member; the decision node still decides bid or skip. Off by default. Design: ADR 0006; commit 4fcd2c1. Not built: the brief's "drafts in that member's voice" (dropped: measuring it needs many LLM drafts under the Groq cap).

How we measured it (evals/runners/agency_routing.py, the same fit_for and route the API calls, no LLM). Source: agency_routing_dev.json.

9. Safety and platform respect

GigBid must never: send a proposal or message, or spend Connects, without the user's approval; scrape or automate a website; invent portfolio experience; leak personal data or tokens.

  • Approval by structure. Submit and send are graph nodes reachable only after an approved interrupt(); before it, write tools run only with dry_run=true. An edited draft is re-checked by Compliance and, if blocked, goes back to the user. Idempotency keys make a resumed or replayed run submit once.
  • Least privilege. Each node gets only its allowlisted tools; the Marketplace server adds Bearer auth, a rate limiter under GigSim's limits and an audit log.
  • Untrusted input. The writer and client liaison wrap posts and messages in delimiters; the Risk Assessor flags injected instructions. Injection attack success at the decision: 0.217 without that signal, 0.0 as shipped (23 posts, injection_dev.json; the signal was written after seeing dev jobs, so this is optimistic).
  • Grounding. The Verifier checks every claim (R5); Compliance strips contact details, guarantees and off-platform asks.
  • Privacy. PII masked in logs and Langfuse spans; OAuth tokens encrypted per user; every query scoped to the account.

What still gets through: scams without a matching pattern (5 of 8 scams in the smoke sample were bid on, §8); unsupported claims after verification (0.222 per V1 proposal); whether the writer model would obey an injection that gets past the decision is not measured (evals/runners/injection_writer.py was not run).
